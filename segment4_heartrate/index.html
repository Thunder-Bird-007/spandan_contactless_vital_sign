Segment 4: CHROM/POS Pulse Extraction & FFT Heart Rate

This is the documentation site for Segment 4 of the Spandan project (contactless heart-rate & SpO2 estimation from ordinary video — EEE 312 DSP Lab, BUET). Segment 4 takes the cleaned, bandpass-filtered R(t), G(t), B(t) traces that Segment 3 produced and combines them into a single pulse signal using the published CHROM and POS algorithms, then estimates heart rate via FFT peak-picking — run on the CHROM signal, the POS signal, and the raw green channel alone, so the team has three independent estimates to compare. Nothing here does SpO2 ratio-of-ratios/calibration or LOSO validation — those are later segments.

CHROM (de Haan & Jeanne, 2013) POS (Wang et al., 2017) FFT peak-picking 0.7–4 Hz search band MATLAB

The code

The actual implementation lives in the main project scaffold, not in this docs folder:

  • matlab/src/pulseextraction/chromCombine.m — CHROM channel combination.
  • matlab/src/pulseextraction/posCombine.m — POS channel combination.
  • matlab/src/heartrate/fftHeartRate.m — FFT peak-picking in the 0.7–4 Hz band, converted to bpm.
  • matlab/scripts/run_segment4_heartrate_batch.m — batch driver the team runs over their filtered subjects.

What comes out of this segment

For every subject processed: data/processed/<subjectID>_hr_estimates.mat (fields HR_chrom, HR_pos, HR_green, HR_groundtruth, subjectID, fs), one appended row in the shared results/metrics/segment4_hr_summary.csv, and results/figures/<subjectID>_heartrate_sanity.png — three stacked FFT spectra (CHROM, POS, green-only), each restricted to 0–5 Hz with the valid 0.7–4 Hz band shaded and the detected peak marked. Always look at the PNG before trusting a subject's numbers — you want one clean, obvious peak inside the shaded band for CHROM and POS, not scattered, ambiguous energy.
