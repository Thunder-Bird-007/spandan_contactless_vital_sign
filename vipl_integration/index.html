VIPL Integration: Dataset I/O Adapter

This is the documentation site for the VIPL-HR integration of the Spandan project (contactless heart-rate & SpO2 estimation from ordinary video — EEE 312 DSP Lab, BUET). This is an I/O integration note, not new DSP theory — Segments 2–5 (face/ROI extraction, filtering, CHROM/POS/FFT heart rate, SpO2 ratio-of-ratios + calibration) are completely untouched. UBFC-rPPG gave this project SpO2 ground truth for only 5 subjects across a narrow 96–99% range; VIPL-HR ships 107 subjects with real HR and SpO2 ground truth across 9 recording scenarios each. Everything on this page is about getting that second dataset feeding into the same, already-tested pipeline through two new loader functions — nothing more.

The code

The actual implementation lives in the main project scaffold, not in this docs folder:

  • matlab/src/io/loadVIPLVideo.m — opens a VIPL-HR video, recomputes the real frame rate from time.txt whenever one exists.
  • matlab/src/io/loadVIPLGroundTruth.m — parses VIPL-HR's per-second HR/SpO2 ground-truth files into the same shape Segments 4–5 already expect.
  • matlab/scripts/run_vipl_integration_batch.m — batch driver the team runs over their assigned (subject, scenario, source) triples.
  • docs/VIPL_DATA_FORMAT.md — the full, file-verified format writeup; read before touching the loaders.

What comes out of this segment

For every (subject, scenario, source) triple processed: the same data/processed/<subjectID>_rgb_traces.mat shape UBFC subjects already use, saved under a collision-safe VIPL_p<N>_v<scenario>_source<S> subject ID. HR/SpO2 summary CSVs (segment4_hr_summary_vipl.csv, segment5_vipl_calibration.csv) carry an explicit dataset column, so Segment 6 can tell which dataset any pooled row came from without a lookup table. The initial 3-subject validation run (p1/p2/p3, scenario v1 "stable", source1 webcam) landed CHROM/POS heart rate within about 1–6 bpm of ground truth on all 3 subjects, and a 3-subject leave-one-out SpO2 calibration MAE of 3.1 percentage points — proof the code path works end-to-end on real VIPL-HR data, not yet a validated calibration on its own (that's Segment 6's job, across the full pooled subject count).
